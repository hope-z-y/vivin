# vivin 功能需求草稿

状态：核心功能范围已确认，技术细节待设计（2026-10-23）

## 产品定位

vivin 是面向个人使用的离线 Markdown 桌面应用。用户以项目组织文档，在排版后的文档中直接写作，并通过全文搜索、术语解释、批注和多栏查看理解与维护内容。

首发平台：macOS。

首个可用版本必须提供 Codex 可用的本机控制接口，而不是等手动功能完成后再添加。

## 已确认的原则

- 应用离线运行，主要供个人使用。
- 一个项目对应本地的一个文件夹。文档、术语、批注等数据按项目隔离。
- Markdown 文件保持干净，只保存正文；术语定义、术语匹配例外和批注保存在项目的独立数据中。
- 项目内的图片等附件使用相对路径，使整个项目文件夹可以一起移动。
- 复制整个项目文件夹给其他人后，对方打开时应看到相同的目录结构、文档内容、图片、资源库文件、术语、标注、固定和锁定状态。项目数据不得依赖原电脑上的绝对路径。最近打开的文档、分栏布局和滚动位置等个人窗口状态不要求一致。

## 核心功能

### 项目与文件

- 创建项目、打开已有项目文件夹。一个项目可包含多个文档和多级目录；应用内的项目树与磁盘上的文件夹结构一致。
- 在项目树中创建、重命名、移动和删除目录或 Markdown 文档；实际文件系统随操作同步变化。
- 支持固定多个文档；固定的文档排在其所在目录的文档列表上方。固定状态随项目文件夹一起复制。
- 支持锁定文档或目录，并保存锁定状态。锁定目录后，其下所有子目录和文档自动继承锁定；解锁目录后，文档自身的锁定状态仍然保留。
- 锁定文档打开时只显示 Markdown 原文，且不允许编辑。锁定状态也应约束外部控制接口的写操作。
- 切换项目时，仅显示该项目的文档、术语、批注和搜索结果。
- 粘贴或拖入图片时，将图片保存到项目内的附件文件夹，并在 Markdown 中插入相对路径。

### 资源库

- 每个项目根目录下使用 `resources/` 文件夹作为资源库。它是普通可见文件夹，便于在 Finder 中直接放入来源文件；与 Markdown 图片附件目录分开。
- vivin 在项目侧边栏中单独展示资源库，只显示文件名称和文件类型；不解析文件内容、不生成预览，也不纳入全文搜索。
- 将外部文件加入资源库时，复制文件到项目内，确保复制整个项目文件夹给别人后资源文件仍然存在。
- 本机接口可列出当前项目的资源文件，并返回其本机路径，供 Codex 在用户要求整理文档时自行读取原文件；vivin 不代替 Codex 解析资源内容。项目数据中只保存相对路径，不保存当前电脑的绝对路径。

### 写作编辑

- 提供类似 Typora 的所见即所得编辑体验，在排版后的文档中直接写作。
- 在文档上提供“Markdown 原文”和“排版预览”的切换入口。两种视图均可编辑；锁定文档只显示不可编辑的原文。
- 保存为普通 `.md` 文件。
- 第一版计划覆盖标题、段落、强调、链接、列表、待办项、引用、代码块、表格和图片等常用 Markdown 内容。
- 编辑界面中可直接使用术语悬停和选区批注。
- 检测到其他程序修改当前文档时提示用户刷新，不静默覆盖磁盘上的外部改动。

### 全文搜索

- 默认搜索当前项目内的 Markdown 正文。
- 展示包含上下文的命中结果，并可跳转到文档中的命中位置。
- 首版不搜索术语解释、标注说明或资源库文件内容。

### 术语解释

- 在项目内创建、编辑和删除术语及其解释。一份解释在该项目的多篇文档中共用。
- 提供独立的项目术语列表，便于浏览和维护术语。
- 自动识别文档中的同名术语；鼠标悬停时显示解释，无需改写 Markdown 正文。
- 允许对个别出现位置关闭自动解释。

### 文档标注与位置缩略图

- 用户可选中一个词、字段或一段内容，添加以下类型的标注：待办、普通批注、错误、疑问。待办标注与 Markdown 正文中的任务列表是两种独立内容。
- 四类标注都允许附加说明，说明可留空，以便快速标记位置。
- 已添加的标注说明可后续编辑。
- 这些是标注类型，不具有“未处理／已解决”等状态；标注与选中的原文位置关联，数据独立于 Markdown 正文保存。
- 在文档中显示轻量标记。编辑原文后，应尽量维持标注与原文的关联；无法准确定位时需明确提示，避免错误地挂到别处。
- 在长文档右侧提供位置缩略图（minimap），按文档中的大致位置展示各类标注的标记，便于发现问题分布并快速跳转。
- 不同标注类型在缩略图和正文中可区分；点击标记可定位到原文并查看详情。
- minimap 可按标注类型筛选显示。
- 用户线下确认后可直接修改正文，再删除对应标注；删除标注只移除附加标记，不删除或改写 Markdown 原文。
- 标注跟随项目文件夹复制；不写入 Markdown 正文。

### 多栏查看

- 支持左右两栏，每栏独立打开和编辑文档。
- 允许在两栏中打开同一篇文档，进行对照阅读或编辑。

### 本地 AI 控制接口

- 本节能力属于首个可用版本的必需范围。
- 提供类似 MCP 的本机接口，让本机 Codex 能操作 vivin。这里的“本地”指通过本机接口操作应用，不要求 AI 模型在本机推理。接口至少支持创建项目、管理项目树、读取及修改文档、添加和删除普通批注、待办、错误及疑问标注。
- 每个项目根目录使用 `AGENTS.md` 保存给 Codex 阅读的写作规则，包括文档风格、结构、术语用法和示例。该文件随项目文件夹复制，也可在 vivin 中编辑。
- AI 对某个项目执行操作时，必须遵循该项目的 `AGENTS.md`；本机接口应主动提供当前项目的规则，不能依赖 Codex 的工作目录恰好位于该项目内。
- 固定、锁定、术语和标注等应用状态保存在独立的结构化项目数据中，不写入 `AGENTS.md` 或文档正文。
- AI 的操作应遵守项目隔离和文档锁定状态，并返回明确的成功或失败结果。
- AI 可直接执行写入操作，无需每次修改前由用户确认。
- AI 的写入应保留可查看、可撤销的修改记录。
- 首版中 vivin 在后台运行时，本机接口仍可供 Codex 操作；应用完全退出后的操作不属于首版必需范围。
- 接口仅面向本机使用，不要求账号或云服务。

## 设计阶段待定细节

1. 项目规则之间出现冲突时如何提示和处理，仍需定义。
2. 可撤销修改记录的保留范围与期限，仍需定义。

## 暂不作为已确认需求

云同步、账号、多人实时协作、PDF/Word 编辑以及超过两栏的分屏，均未纳入当前需求。后续可以根据使用场景再评估。
